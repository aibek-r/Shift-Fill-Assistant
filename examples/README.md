# Example workflows

Each example has a readable report (`.md`) and the full structured output (`.json`), including
the trace of every model and tool step.

## Provenance

| Example | How it was produced | Current? |
| --- | --- | --- |
| 01-05 | Live model runs (the configured `gpt-5.4-mini`) generated by `scripts/run_examples.py`, last committed on October 4, 2026, before the latest reliability changes | **Need live regeneration** before they can be shown as current behavior (details below) |
| 06 | Rule-based fallback (simulated outage), regenerated offline from the current code with `python scripts/run_examples.py --offline` | Yes |

The agent examples are historical outputs and have not been edited. Code changed after they were
recorded:

- **01 and 02** quote preference wording from profile free text ("Profile wording
  (self-reported): ..."). The current code uses structured preference fields instead. They also
  lack the per-recommendation provenance fields (`selected_by`, `outreach_by`).
- **01, 02 and 05** have no `completion` step in their traces. The current workflow always runs
  one after a completed submission. Their outcomes match the current completion conditions:
  each vetted the full pool, and 01 and 02 drafted all requested outreach.
- **03 and 04** use clarification paths whose code did not change. They were produced with the
  earlier prompt.
- The system prompt's ranking rubric changed (structured `period_fit`), so live rankings may
  differ.

To regenerate everything, run `python scripts/run_examples.py` with `OPENAI_API_KEY` set. This
makes paid API calls. Model wording and ranking vary between runs; compliance verdicts do not.

## The examples

1. **[ICU night shift](01-icu-night-shift.md)** (agent). The agent resolves the shift, retrieves
   the ICU profile, searches and vets all 9 ICU nurses, and drafts outreach. The eligibility
   engine excludes 6 nurses, each with a reason code. Daniel Kim is eligible but has an expiring
   ACLS certificate, so the agent ranks him below two clinicians without warnings, and he is
   listed under "Alternates", which code computes.
2. **[PICU shortlist with a warning](02-picu-shortlist-with-warning.md)** (agent). The coordinator
   asks for a shortlist of two for one opening. Liam Chen's PALS expires 22 days after the shift;
   the warning appears in his explanation, and his draft gets a renewal reminder. Emma Davis is
   excluded because California does not accept compact licenses.
3. **[Ambiguous request](03-ambiguous-request.md)** (agent). "An ICU nurse for St. Mary's next
   week" matches no shift in the week after the pinned reference date. The agent asks instead of
   guessing.
4. **[Unknown facility](04-unknown-facility.md)** (agent). The tool error lists the known
   facilities, and the agent turns it into a clarifying question.
5. **[Nobody eligible](05-no-eligible-candidates.md)** (agent). All three NICU candidates fail:
   one has an expired NRP, one has too little experience, and one has an expired license. The
   full pool was vetted, so `no_eligible_candidates` is a verified result.
6. **[LLM outage](06-llm-outage-fallback.md)** (fallback). Every model call fails, and the
   workflow degrades to the rule-based fallback. It applies the same eligibility engine and
   templates, and labels every recommendation and draft as produced by rules.

Repair, enforcement, deterministic completion, needs_review and budget exhaustion cannot be
triggered on demand with a live model. They are covered by the scripted tests and by
`python -m evals.run` (see `docs/DEMO.md`).
